## 2. 每一步的固定字段（两人必须一致，否则最后拼不起来）

每条路径拆成若干步，每步固定六项：

```text
### 第 N 步 · 步骤名称
- 为什么是这一步，而不是更后面的内容：
- 先弄懂什么：
- 做完怎样算过了：        ← 必须是能交出来的东西，不能写「理解了」
- 依据：                  ← 材料题目 + 链接
- 对应现在树上的哪个节点：  ← 没有就写「建议新增」
```

三条写法纪律：

1. **卡点驱动**：每一步的「为什么」要指出**上一步会在哪里卡住**，而不是罗列这门学科的知识点。
2. **过关标准可核对**：默认形式是「交一份东西给谁看」，判据要客观（例如「每行注明依据」「按类看混淆矩阵」）。
3. **终点停在本科生进得去的深度**：能读、能复现、能写出一份可给人看的小结，不承诺做出新结果。

## 3. 主链标注约定（给任务 1 的前端）

现有树是**领域树**（概念之间的从属关系），路径是**带顺序的主链**。两者不冲突：把路径作为主干嵌进树。

- 每条路径的 6 步 = 6 个**主干节点**，按 `stage: 1..6` 排序；
- 主干节点标 `main: true`，前端用一条连线串起来，其余保留为岔路节点；
- 现有概念节点不删，挂到对应步骤下面当「这一步要弄懂的东西」；
- 建议的数据形状（不含实现，供讨论）：

```js
{ id: "math-s2", label: "把极限说严格", intro: "…",
  stage: 2, main: true, children: [ /* 原有概念节点 */ ] }
```

- 两人合并后，四个方向应导出**同一种形状**；谁改 `FIELD_TREES` 由任务 1 统一安排，本目录不产出代码改动。
