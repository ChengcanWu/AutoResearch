# 改树建议 · 数学 / 人工智能 / 认知 / 经济

> 给**任务 1（前端）**和**任务 3（项目）**的节点改动建议。负责：乙（数学、人工智能）；甲（认知、经济）。
> **本文件不改代码。** 真正改 `FIELD_TREES` 要等四人路径合到一起、两人对过之后再动；甲的两个方向（认知、经济）已于 2026-10-01 合并进本文件（§7、§8）。

## 1. 现状（`web/js/app.js` 的 `FIELD_TREES`）

两个方向都是四层，但形状不同：

- `math`：root「证明是什么」→ 定义 / 证明 / 结构 → 再往下 1–2 层。
  问题：**整棵树只讲「怎么写证明」，没有「学什么」**。学生按它走完，会写证明但不知道下一步该学什么。
- `ai`：root「看懂机器学习」→ 数据 / 模型怎么学 / 用起来。
  问题：**直接从模型讲起，没有先修**（线代、概率、编程）。另外「评估」藏在「模型怎么学」的第二层，但它是这一步最重要的事，位置太低。

- `psy`：root「人如何做判断」→ 知觉 / 记忆 / 决策。
  优点：整棵树就是「用可重复任务代替自我报告」的写法，root 说明可以直接当路径第 1 步的引言。
  问题：**只有「效应是什么」，没有「怎么设计实验」**；也没有统计层和论文阅读层。
- `econ`：root「选择与激励」→ 约束 / 激励 / 市场。
  优点：三层正好对应路径的前三步（成本、激励、价格），节点文字质量高、够用。
  问题：**整棵树是纯概念，没有「数据」层**——而实证经济学的工作全在数据上，这是最大的缺口。

四棵树长度相当（4 层左右），分支数不同，合并时建议统一到「6 步主链 + 保留原有概念枝」。

## 2. 主链方案

每条路径取 6 个主干节点，编号 `stage: 1..6`，标 `main: true`。前端把主干连成一条线，原有概念节点作为岔路挂在对应步骤下。

**为什么要这么做**：现有树回答的是「这个概念属于哪」，路径回答的是「我先做什么」。两者都保留，学生才既看得到地图，也知道下一步。

**关键约定**：树上原有节点讲的是「**二十分钟能做什么**」，主干步骤讲的是「**这一学期走到哪**」。两者尺度不同，前端要能一眼区分（例如主干用实线 + 序号，节点保持现在的样式）。不要把两种尺度混在同一层。

```js
// 建议的数据形状（供讨论，未实现）
{ id: "math-s3", label: "矩阵是映射", intro: "…",
  stage: 3, main: true, children: [ /* 原有概念节点 */ ] }
```

## 3. 数学方向：改动清单

| 节点 | 动作 | 理由 |
| --- | --- | --- |
| `证明是什么`（root）及 `定义` / `证明` 全部子节点 | **保留，整个挂到 stage 1** | 与「把显然拆成步骤」完全对应，内容已经够用 |
| `结构` → `关系` / `不变量` | **移动**到 stage 3 下 | 它讲的是「什么被保留了」，本质是线代与代数的问题，放在「证明」旁边没有去向 |
| `把极限说严格` | **新增**（stage 2，主干） | 现有树最大跳步：没有实数与极限这一层，后面全接不上 |
| `矩阵是映射` | **新增**（stage 3，主干） | 高维对象的公共语言，缺这一层 |
| `带着不确定性说话` | **新增**（stage 4，主干） | 与 `stat` 领域互链，标注为「横向补充」 |
| `读论文：把定义依赖画出来` | **新增**（stage 5，主干） | 从课内材料到研究材料的转换，现有树完全没有 |
| `做一个小问题` | **新增**（stage 6，主干） | 从读到做的转换层，现有树停在「理解」 |

## 4. 人工智能方向：改动清单

| 节点 | 动作 | 理由 |
| --- | --- | --- |
| `数据` 整支（例子从哪来 / 特征） | **保留，挂到 stage 2** | 与「先学会评估」配合使用，位置不变 |
| `模型怎么学` 整支 | **保留，挂到 stage 2–3** | `损失` / `训练曲线` / `过拟合` 直接对应深度学习那一步 |
| `评价` → `别只看准确率` / `误差从哪来` | **上提一层**到主干附近 | 「先写判据再看结果」是第 2 步的核心，藏在第二层太深 |
| `用起来`（预测一件事 / 生成） | **保留，标为 stage 6 的入口** | 它是 20 分钟尺度的小任务，是通往小研究的入口，不是终点 |
| `先修：线代、概率、Python` | **新增**（stage 1，主干） | 现在最大的跳步：公式看不懂、代码写不出来都卡在这里 |
| `深度学习：可复现的训练` | **新增**（stage 3，主干） | 含环境与随机种子的「可复现」层，现有树没有 |
| `读论文：从综述到经典` | **新增**（stage 4，主干） | 同上 |
| `复现实验` | **新增**（stage 5，主干） | 最容易被跳过、也最区分学生与研究者的一步 |
| `卡住的地方就是题目` | **新增**（stage 6，主干） | 把「我没懂」的清单变成可检验的假设 |

## 5. 给任务 3（找项目）的接口

路径上的 6 个阶段可以直接当检索输入的第二项：

```text
输入 = 方向（数学 / 人工智能）+ 当前阶段（stage 1–6）
输出 = 该阶段做得动的公开项目（含来源链接、检索时间）
```

建议的阶段—项目对应关系（供任务 3 参考，不是硬规定）：

| 阶段 | 项目形态 |
| --- | --- |
| stage 1–2 | 复现一个小基线、把一个小结跑出来（Kaggle 入门赛、课程公开作业题） |
| stage 3 | 复现一个小任务的 3 组设置对比 |
| stage 4–5 | 复现一篇经典论文的小子集结果 |
| stage 6 | 一次改进或消融，写成含失败分析的实验报告 |

## 7. 认知方向：改动清单

| 节点 | 动作 | 理由 |
| --- | --- | --- |
| `人如何做判断`（root）及 `知觉→错觉→上下文` | **保留，挂到 stage 1** | root 的说明本身就是「可测行为代替自我报告」的引言；`错觉→上下文` 是最好的操作化示例 |
| `知觉→注意→漏看`、`记忆` 整支、`决策` 整支 | **保留，挂到 stage 2** | 变化盲视、提取练习、误导提问、锚定——都是第 2 步「亲手跑任务」的素材库 |

| `读论文：先读方法` | **新增**（stage 5，主干） | 从课内材料到研究材料的转换层，现有树完全没有 |
