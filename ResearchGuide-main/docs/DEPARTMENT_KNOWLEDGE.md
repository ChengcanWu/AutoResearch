# 院系认知 · 从「国标学科」到「院系-专业」

> 结论先行：**不要上向量 RAG，做一个结构化知识包 + 确定性查表**。
> 数据源用《北京大学本科培养方案》PDF，抽成 `院系 → 专业 → 学分结构 → 课程表 → 课程结构指纹`。
> 本文件是方案；实跑结果与验证见 §6，工具在 `tools/curriculum/`。

---

## 1. 现在缺什么（对着代码说）

| 现有资产 | 说的是什么 | 缺的是什么 |
| --- | --- | --- |
| `knowledge/disciplines.json`（988 KB） | GB/T 13745 国标学科：门类 A–E → 一级 110 数学 → 二级 110.11 数学史 | **不是北大院系**。学生说「我是元培的」「我想转信管」，这里没有对应的东西 |
| `knowledge/direction_tree.json` | 上面这份的子集 | 同上；节点是国标代码 |
| `knowledge/tutorials/*.json` | 按国标代码（`790.45`）挂的入门路径 | 与院系-专业无映射，学生无法从「我的专业」走到这里 |
| `knowledge/catalog/`（3097 门课快照） | 本学期公开课：课名、老师、**开课院系**、学分、类别 | 没有「哪些专业把它列为必修」的反向索引，也没有必修结构可比对 |
| `server/planner.py` `DIRECTIONS` | 7 个人工策展方向，`discipline_ref` 写的是「数学（110）」「经济学（790）」 | 国标口径；与培养方案、院系无关 |
| `server/transcript.py` | 能从成绩单解析出课程 | 解析出来后**没有专业结构可比对**，只能让模型自由发挥 |

一句话：**产品懂「学科世界」，不懂「北大」。** 而北大本科生实际是按
`学部 → 院系 → 专业 → 培养方案（学分结构 + 课程表）` 生活的：转专业、辅修、双学位、选课、保研，
全部走这套口径。院系认知不是给 AI 多塞一点背景知识，是补上这四个决策问题：

1. 这个学生大概率在哪个院系 / 专业？（现在只能靠用户自己说）
2. 这个专业的必修结构是什么？他现在缺哪一块？
3. 这门课是谁开的、哪些专业必修它？
4. 这个专业在大几该出现哪些课？（现在的「下一步」给不出学期感）

## 2. 方案对比：结构化知识包 vs 向量 RAG

| | 结构化知识包 + 查表（推荐） | 向量 RAG |
| --- | --- | --- |
| 培养方案这种强结构数据 | 表格、学分、模块编号原样保留，查「经济学的数学课学分」100% 确定 | 切块后结构被打散，可能召回社会学的高数 D（名字像、要求差一个等级） |
| 可溯源 | 每条带 `来源页`，能指到 PDF 第几页 | chunk 只能指到「大概哪一段」 |
| 维护 | 加一年 = 重跑一次脚本 | 要重建索引 + 调 chunk 参数 |
| 依赖 | 无（JSON + 内存/SQLite） | 嵌入服务 + 向量库；校园单机部署多两个运维面 |
| 与现有架构 | 与 `ARCHITECTURE.md` ADR #7「不做向量 RAG：知识包小而结构化」一致 | 推翻 ADR #7 |

**推荐路线**：结构化知识包当主路，自然语言只用来**抽槽位**。
用户说「我大二，数学还行，想做偏数据的方向」→ 模型只负责抽成
`{年级:大二, 数学:中, 关键词:[数据]}`，然后查表排序；模型不负责记事实。

**诚实的边界**：如果知识源以后扩到「选课手册 + 教务通知 + 课程大纲 + 往届经验帖」这类几千篇长文本，
结构化字段答不了的问题会变多。那时的第一选择仍然是 **SQLite FTS5 关键词检索**（零新依赖），
只有在关键词也答不好的比例被日志证明超过阈值时，再评估向量层。**先别上。**

## 3. 数据设计（五层，按「要不要塞进 prompt」分）

```text
L-1 卡层     cards.json            专业卡：院系/门类/专业类/学位/学制 + 一句定位 + 代表性必修课
                                    + 数学计算底子 + 检索别名（199 条，227 KB）——AI 直接读的就是这一层
L0  骨架     catalog.json          院系 × 专业：专业代码 / 门类 / 专业类 / 学位 / 学制（150 条，本部全院系）
L1  结构     plans/<专业>.json      毕业总学分、学分结构、按模块归类的课程表（含选修菜单）、来源页、卷
L2  指纹     fingerprints.json      必修学分、数学/计算/语言/实践学分、课号前缀、学期分布
L3  反查     course_index.json      课号 → 哪些专业把它列为必修
             prefix_ownership.json  课号前 4 位 → 谁在必修它（用数据自证「课号能认院系」）
共享         public_courses.json   公共基础课程（思政/体育/英语/信息科学/通识）全校一致，只存一份
辅修层       knowledge/minor/       辅修 / 双专业：学分要求、核心课程、**替代课程**（98 条，另一个 PDF）
```

两卷合成一个知识包：**文科卷 + 理科卷**共用同一份《北京大学在用本科专业目录（本部）》（150 条），
所以 `catalog.json` 只有一份，某条专业在哪一卷有培养方案看 `plans/*.json` 的 `卷` 字段
（`文科卷 / 理科卷 / 文科卷/理科卷`，公共课章节两卷完全一样，标后者）。

**哪些东西故意不重复存**（都是「存 N 遍没有任何信息增益」）：
公共基础课程（每个专业都一样的 43～49 学分，摘成一份共享文件）；同一份课程表不存两遍
（`课程_去重` 可由 `课程表` 摊平得到，已删）；辅修层独立成目录，因为它的主键是
`(院系, 专业, 双专业|辅修)`，不是「学生的主修专业」；**一份培养方案覆盖多个专业目录条目时只出一张卡**
（例：物理学院 p112 那一章同时是「物理学 / 物理学（大气物理方向）/ 物理学（天体物理方向）」，
化学与分子工程学院 p168 同时是「化学（材料化学方向）070301」与「材料化学 080403」）——
被覆盖的条目收进卡里的 `目录条目`，这样 AI 不会把同一份内容读两遍。

### 3.1 怎么按名字查到（检索别名）

同一个专业在库里至少有三种写法，硬比字符串必然查不到：

| 写法 | 例子 | 来源 |
| --- | --- | --- |
| 章节名（= `plans/*.json` 的键、`intros.json` 的键） | `汉语言文学专业`、`信息与计算科学专业（图灵班）` | 培养方案正文的标题 |
| 专业目录名 | `汉语言文学`、`信息与计算科学（图灵班）` | 《在用本科专业目录》那 150 行 |
| 口语（去「专业」二字、去方向括号） | `汉语言文学`、`信息与计算科学`、`软件工程专业` | 用户/前端怎么问 |

所以每张卡带 `检索别名`（199 张卡共 **499 个检索键**），`tools/curriculum/lookup.py` 按
「主键完全相同 → 别名表 → 包含匹配 → 最像的 3 个名字」四层查，并**保留歧义**：
一个名字对上多个专业时返回全部候选（`经济学` → 3 个、`信息与计算科学` → 8 个、
`理论与应用力学` → 9 个，全库 66 个这样的入口），这正是产品要输出的「专业簇」。

与现有资产的关系（**不是取代**）：

```text
国标学科层（已有）    disciplines.json / tutorials / direction_tree
        ↕  需要一张映射：院系-专业 → 1–2 个国标学科代码（可先用课号前缀 + 专业类自动出初稿，再人工核 26×150）
院系-专业层（本方案） cards / catalog / plans / fingerprints / course_index
        ↕  join 现有 knowledge/catalog/（本学期真开了哪些课、开课院系、学分）
课程现实层（已有）    3097 门公开课快照 + skills/pku-course 实时检索
```

**挤水分**：结构化字段里**只**放能参与判断的东西。
`一、专业简介`、`二、培养目标`、`三、培养要求`、师资荣誉、联系方式、课程地图图示、
港澳台/留学生政策附注 —— 原文一个字都不进结构化字段；唯一保留的是从「培养目标 + 代表性必修课」
蒸馏出来的一句 ≤40 字定位（见 §5 的蒸馏流程）。
判据只有一条：**这条信息会不会改变「下一步做什么」的判断？** 不会就不进库。

### 3.1 那句「这个专业是干什么的」怎么来的

培养方案这部分全是套话，**自动抽出来的原句不能直接用**——实跑抽到过：

- 「历年来培养了大量的社会学专业人才。」
- 「艺术学院现有教师33人，其中教授15人，长聘副教授9人……」
- 「数智金融项目」的培养目标段落里混进了另一个项目（新闻传播）的整段文字。

所以流程是三步，而不是一步：

```text
distill.py --make-batches   抽「一、专业简介 / 二、培养目标」原文 + 代表性必修课 → 按卷分批
     ↓                       （原文另存 prose_raw.json，只用于对照，不进库）
LLM 压成 ≤40 字，只许依据原文与必修课，禁词表：师资/教授/人数/沿革/荣誉/排名/评估/招生/复合型人才…
     ↓
merge_intros.py             多卷/多层的蒸馏结果合并 + 冲突检查（同一专业两次写法不一致会报出来）
     ↓
docs/curriculum_intros_review.md   一句一行，左边蒸馏句、右边原文片段，人工抽检
```

本次两卷共出 **179 条定位句**（文科卷 89 + 理科卷 90，无冲突），抽检表里单列了
**22 条信息稀薄条目**（原文与必修课都稀疏，如「人文+AI 能力提升证书项目」「博雅AI4S 拔尖人才培养计划项目」
「教育心理学项目」，理科卷的「电子信息科学类实验班（信班）」「整合科学」也属这类）——
这几条必须人工确认或标注为待补，**不要当成可信的画像**。

## 4. AI 怎么用

### 4.1 认知卡（进上下文的固定格式）

不需要把整个专业塞进 prompt。给一张卡，约 300 token，全部是查表结果、全部带来源：

```text
【院系-专业】经济学院 / 经济学专业
【学位与总学分】经济学学士学位 · 毕业总学分 131学分
【学分结构（大类）】2 专业必修课程 51学分｜3 选修课程 31～37学分
【学分结构（细分）】2-1 专业基础课 38学分｜2-2 专业核心课 10学分｜2-3 毕业论文（设计） 3学分｜3-1 专业选修课 26学分｜3-2 自主选修课 5～11学分
【公共基础课程】全校统一 公共基础课程 43～49学分（明细见 public_courses.json，plans 里已摘走）
【必修分量】方案要求「51学分」；课程表内必修课 48 学分 / 16 门（数学 20 · 计算 0 · 语言 0 · 实践 1）
【开课院系线索（课号前 4 位：学分）】0253→31（经济学院）、0013→17（数学科学学院）
【大一就会出现】高等数学（B）（一）5（一上）、经济学原理（Ⅰ）3（一上）、政治经济学原理 3（一上）…
【数学底子（必修）】高等数学（B）（一）（二）、线性代数（B）、概率统计（B）、计量经济学
【来源】《北京大学本科培养方案（2026）文科卷》书内 p524（PDF p532–537）
```

理科卷同一个模板，多了「合章」这条（理科卷把两个专业印在一章里，两份方案本来就相同）：

```text
【院系-专业】地球与空间科学学院 / 地球化学专业
【学位与总学分】理学学士 · 毕业总学分 143～149
【学分结构（大类）】2 专业必修课程 53学分｜3 选修课程 47学分
【公共基础课程】全校统一 公共基础课程 43～49学分
【必修分量】方案要求「53学分」；课程表内必修课 49 学分 / 14 门（数学 10 · 计算 0 · 语言 0 · 实践 0）
【开课院系线索（课号前 4 位：学分）】0123→27（地球与空间科学学院）、0013→10、0043→8
【大一就会出现】高等数学（B）（一）5（一上）、普通化学4（一上）、行星地球科学3（一上）…
【数学底子（必修）】高等数学（B）（一）、高等数学（B）（二）
【来源】《北京大学本科培养方案（2026）理科卷》书内 p245（PDF p251–259）
【合章】与 地质学专业 印在同一章，课程表相同（原文就没分开印）
```

`tools/curriculum/card.py` 就是这张卡的最小实现（`--major 经济学专业`）。

规则（写进系统提示）：**卡里有的才说，卡里没有的说「培养方案里没写」**；要给更细的课程时再查 L1。

### 4.2 三个落地场景

1. **拿成绩单认院系**（直接接 `server/transcript.py`）
   解析出课号 → L3 反查 → 按覆盖率/F1 给院系-专业排序 → 输出：
   「你修过的课更像**经济学院**（命中 12 门必修）；离经济学专业的必修结构还差 `概率统计（B）`、`计量经济学`」
   → NBA 落到「下学期修概率统计（B）」，而不是泛泛的「建议加强数学」。
2. **方向树挂上真实专业**
   现在树节点挂的是国标学科 + 课程检索；改为可挂到「院系-专业」，点开能看到该专业真实的
   学分结构与学期分布，学生一眼看到「这条路前两年长什么样」。
3. **选课 / 转专业 / 辅修建议**
   给「专业 + 当前学期」→ 输出该专业这一学期该出现的课 + 缺的先修课，并注明依据页码。
   如果学生修了辅修/双专业，再查 `knowledge/minor/`：主修修过同名课就要看该章节的
   **替代课程**（原文「说明」后面那张表），不能直接说「你已经修过了，不用再修」。

### 4.3 接口（已实装，`server/curriculum.py` + `server/main.py`）

查表这件事已经落地成两层，都是**只读 JSON、不联网、不调模型**：

```powershell
# 命令行（离线抽查 / 数据回归用）
python tools/curriculum/lookup.py --kb knowledge/curriculum --ask 软件工程专业
python tools/curriculum/lookup.py --kb knowledge/curriculum --ask 经济学          # → 3 个候选（专业簇）
python tools/curriculum/lookup.py --kb knowledge/curriculum --minor --ask 法学辅修

# 服务（产品用）：python server/main.py → 127.0.0.1:8100
GET  /api/explore/majors?q=经济学        → {ok, kind:"专业簇（3 个）", 命中[]}    # kind=唯一|专业簇(N)|未命中
GET  /api/explore/major?name=经济学专业    → {ok, 卡片, 学分结构, 必修课[], 兄弟专业[]}
POST /api/curriculum/match  {codes:[...]} → {ok, 院系排名[], 专业排名[{专业,分,命中数,还缺[]}]}
GET  /api/explore/minor?q=法学辅修|dept=经济学院 → {ok, 命中[]}                    # 含替代课程
GET  /api/explore/course?code=02530060   → {ok, 课程名, 必修它的专业[], 开课院系线索[]}
GET  /api/curriculum/stats               → {ok, 专业卡:199, 培养方案:198, 辅修方案:98, 课程索引:1077}
```

设计要点（都是踩过的坑）：

- **先查表，再让模型说话**。「我是经济学院的」这类问题的答案必须来自这些接口，不能靠模型回忆。
- `find_major` 四层检索 + **保留歧义**：`经济学` 返回 3 个候选、`信息与计算科学` 返回 8 个，
  交给产品输出「专业簇」，而不是硬挑一个。
- `match` 与留一验证同一套 F1 口径（公共必修按「出现在 ≥30% 专业的必修结构里」剔除），
  所以接口给的排名和 §6 报的数字是同一算法；返回里带 `还缺` 名单，可以直接回答「还差哪几门」。
- `major_detail` 会带**同院兄弟专业**：低年级成绩单认不出细分方向，这一步是产品两级输出的落点。
- 辅修方案按**文件名**取键（`院系-专业类型`）：按 `专业` 字段取键会把 98 条并成 56 条（双专业/辅修同名）。
- 课程名在 plans 里的键是 `课程名称`（不是 `课程名`），`course_index` 里也是 `课程名称`；
  按错键会静默拿到空字符串——`server/tests/test_curriculum.py` 里有断言盯着。
- 加载按文件 mtime 失效：改了 JSON 不用重启服务（实测首次加载 ~150 ms，之后命中缓存 ~26 ms）。

测试：`python -m pytest server/tests/test_curriculum.py -q`（18 条，含成绩单认院系、
公共课模块剔除、辅修替代课程、课号反查）；HTTP 层用真服务冒烟过一遍（含 POST match）。

### 4.4 辅修 / 双专业层（`knowledge/minor/`）

单独一份 PDF（《北京大学本科辅修双专业培养方案（2025）》）抽出来的 98 条：
40 个双专业 + 58 个辅修，覆盖 24 个院系。字段和主修层不完全一样：

| 字段 | 为什么要有 |
| --- | --- |
| `类型` | `双专业`（≥40 学分，含部分选修）或 `辅修`（≥30 学分，基本全是核心课） |
| `总学分 / 必修 / 选修` | 照抄原文（`≥40学分` 就是 `≥40学分`，不取中值） |
| `核心课程` | 有条数上限的必修改清单，用来回答「这个辅修在学什么」 |
| `替代课程` | 主修已修同名必修课时改修这些课才算完成——这一层独有的东西 |
| `授予学位` | 辅修**一律不授学位**；写了学位的 43 条全是双专业 |

同一专业在**不同院系是两份方案**：`环境科学`（城市与环境学院 / 工学院）、`经济学`
（国家发展研究院 / 经济学院）课程和学分都不一样，所以卡片 key 带院系前缀，不要合成一条。

### 4.5 同一个知识库的 MCP 服务（`server/mcp_curriculum.py`）

给「别的 AI 客户端」用的入口：把这 6 个查询包成 MCP 工具，任何 MCP 客户端（DSH、Claude Desktop、
Cursor…）接上就能问，不用改产品代码。**工具表只有一份**，两种传输共用：

| 传输 | 怎么起 | 给谁用 |
| --- | --- | --- |
| stdio | `python server/mcp_curriculum.py` | 客户端自己拉进程（DSH/Claude Desktop/Cursor 都支持），不依赖产品服务在跑 |
| streamable-http | 产品服务起来后 `POST http://127.0.0.1:8100/mcp` | 已经在跑 `server/main.py` 的机器，零额外进程 |

工具（都只读本地 JSON，不联网、不调模型）：

| 工具 | 回答什么 | 背后 |
| --- | --- | --- |
| `major_lookup` | 「经济学」是哪个院的 → 唯一命中 / 专业簇(N) / 未命中+近名；**也可直接问院系**（「信管」「信息管理系」）→ 该院全部专业，这就是「有哪些分流」的答案 | `find_major` |
| `major_detail` | 一个专业要修什么：学分结构、必修课（课号/学分/学期）、兄弟专业、来源页 | `major_detail` |
| `match_transcript` | 拿成绩单课号认院系/专业 + **还缺哪几门必修**（`low_only` 只看大一大二） | `match` |
| `minor_programs` | 辅修/双专业要什么，含**替代课程**；可按名字或院系查 | `find_minor` |
| `course_lookup` | 课号反查课程名、哪些专业必修它、课号前缀线索 | `course_detail` |
| `kb_stats` | 库里有多少专业/方案/课程（健康检查） | `stats` |

接进 DSH（改 `~/.dsh/profiles/<profile>/cordis.patch.yml`，DSH 自带的
`dsh-mcp-client` 模板就是这个形状；工具会以 `mcp__<serverName>__<工具名>` 注册）：

```yaml
- insert:
    - id: curriculum-kb          # stdio：自包含，不要求产品服务在跑
      name: '@deepseek-ai/dsh-mcp-client'
      config:
        serverName: curriculum
        transport: stdio
        command: C:\Users\<你的用户名>\AppData\Local\Programs\Python\Python313\python.exe
        args: ['C:\...\ResearchGuide-main\server\mcp_curriculum.py']
        cwd: 'C:\...\ResearchGuide-main'
        failOnStartupError: true
    # 若更想用已经在跑的产品服务，把上面换成：
    # config: {serverName: curriculum, transport: streamable-http, url: 'http://127.0.0.1:8100/mcp'}
```

验证过的原始证据（两种传输都真跑过，不是只过单测）：

```text
stdio : python server/mcp_curriculum.py < mcp_in.jsonl > mcp_out.jsonl
        9 条输入 → 8 条响应（通知不回）、退出码 0、stderr 空
        initialize → protocol 2025-06-18 · tools/list → 6 个工具
        match_transcript(6 门课号) → 院系 经济学院(0.55) · 专业 经济学专业
        minor_programs(法学辅修) → 法学院 法学 30学分 10 门核心课
http  : POST /mcp initialize/tools/list/tools/call → 200（含 structuredContent）
        通知 → 202 空正文；批量 JSON-RPC → 数组；GET /mcp → 工具清单一览
```

设计上故意保留的「不聪明」：一个名字对上多个专业时**返回全部候选**，未知专业返回最像的 3 个名字，
所有回答带来源页。宁可让上层 AI 看到歧义，也不要它把「经济学（国家发展方向）」当成「经济学专业」
硬报给用户。测试：`server/tests/test_mcp_curriculum.py`（13 条，协议握手 + 6 个工具逐个跑）。

### 4.6 同一份工具表也挂进了产品内对话（`server/tools.py`）

外部客户端有 MCP 了，但**产品自己的对话 agent 一开始没有**：问它「信管有哪些专业分流」，
它会答「我手上没有能检索北大培养方案的工具」——工具做出来了，只是没挂进对话的工具 registry。
现在挂上了，而且是**共用同一份定义**：`mcp_curriculum.TOOLS` 是唯一的工具表，
`tools.py` 把它改写成 prompt 里的文字清单，两边都调 `curriculum.py` 的同一套查询函数。

对话侧多做三件代码该做的事（都属于「模型决定调什么，代码决定答案是什么」）：

| 情况 | 代码怎么做 |
| --- | --- |
| 用户问的是**院系**（「信管有哪些专业分流」） | `major_lookup` 认院系简称（`curriculum.DEPT_ALIAS`）与官方名，返回该院全部专业 + 学分 + 核心课，并写明「分流名额以院系教务为准」 |
| 用户**只是提到**院系/专业的简称（「我是信管的大二学生」） | `tools.kb_env_facts()` 在组装环境包时就把该院系的名单查好（最多 2 个名字 × 4 张卡 × 6 门课，带来源页）。**不等他说「帮我查一下」，也不问「你是哪个学校」**——见下一节 |
| 模型把**整句**塞进 `query` | 未命中就按 `curriculum.mentions()` 从原话里找库内名字再查一次 |
| 用户说的是**课名**（或画像里已录成绩单） | `curriculum.codes_for_names()` 用课程索引做确定性反查（归一后完全相同才算命中），认不出的列进 `note`，不模糊猜 |

「课名 → 课号」这一步是必需的：北大成绩单打印件只有课名没有课号，而认院系要课号。
反查之后，一份只有课名的成绩单也能认出「经济学院 / 经济学专业」。

**说到名字就先查，为什么放在代码里？** 用户第一句是「我是信管的大二学生」，「信管」不是
规范院系名，模型那一轮既没查库、又反问了一句「你是哪个学校的？」——而学校本就默认北大。
等模型「想起来」要查，不如让代码在组装环境包时就把名单摆上桌（只读、有界、带来源页，
和按层召回记忆是同一个模式：**代码组装，模型决定怎么用**）。同一次改动里两处：
`memory.LADDER_PROBE["identity"]` 补上 `department`（否则「年级 + 院系」仍被判成身份层空着），
学校改成默认前提 `Slot(presumed="北京大学")`，不主动问、核对页也不留空格。

实跑（真模型，同一段对话）：

```text
我：我是信管的大二学生
   环境包 lib_facts：["信管"] → 信息管理系 3 个专业（代码查的）
→ 回复：「信管大二——你们系三个方向（信息管理与信息系统、图书馆学、大数据管理与应用）
   的必修结构差别不小……这学期你手上在上的课里，哪一门是你真的会花额外时间去弄的？」
   （没有「你是哪个学校」）
我：帮我查一下信管的专业方向
→ 三个专业 + 学分 + 核心必修课 + 来源页（书内 p378 / p387 / p396）+ 分流以教务为准
我：这些方向里哪个更适合以后做数据方面的工作？
→ 按必修清单比较，并如实说清「方向 ≠ 能不能做数据岗」
```

实跑验证（真模型、产品服务上跑的一轮）：

```text
我：我是信息管理系大二的，能帮我查一下信管有哪些专业分流吗
→ 调 major_lookup("信息管理系") → 院系（3 个专业）
   信息管理与信息系统（120102，必修 44 学分）· 图书馆学（120501，38）·
   大数据管理与应用（120108T，46）
→ 回复按三个方向分述核心课与学分，并写明「分流名额/时间/绩点门槛以院系教务为准」

我：那大数据管理与应用专业要修哪些必修课？学分是多少？
→ 调 major_detail → 按学期列出 16 门必修课 + 学分结构，来源：书内 p396（PDF p404–412）

我：我大一学了高等数学（B）（一）、线性代数（B）、计算概论A，这些课像哪个院系的？
→ 调 match_transcript（source=model_names，课名反查出 3 个课号）
→ 回复：这三门是公共基础课，认不出院系（最高只有 0.4），并如实说别在课名上继续找线索
```

测试：`server/tests/test_tools_curriculum.py`（20 条：院系清单、整句兜底、课名反查、
未知专业的覆盖说明、降级路径、以及整轮对话里工具结果确实进了调用②）。

## 5. 抽取的工具与纪律

`tools/curriculum/`（`extract_curriculum.py` / `merge_kb.py` / `merge_intros.py` / `minor_extract.py` /
`compact.py` / `distill.py` / `validate.py` / `review.py` / `card.py` / `check_split.py`，
逐条的坑写在该目录 README 的「抽取契约」里）：

- 只用 `pdfplumber`。这份 PDF 的嵌入字体用 PyMuPDF（fitz）会抽出乱码，pdfplumber 正常。
- 页码：书内页码取页眉页脚的 `·N·`，`PDF 页 = 书内页 + 偏移`（偏移按卷取众数，文理两卷不同）。
- **院系归属按页码区间判**：专业挂在「书内页码在它之前、且最靠后的那个院系」下。目录的排版顺序
  不等于章节顺序——理科卷就不是，按顺序挂会把工学院的专业挂到信息科学技术学院（实跑踩过）。
- **学部名和院系名可能连在一行印**（`工学部北京大学工学院`），必须先剥掉，否则会当成一个「专业」。
- **同一页可以有两个专业**：理科卷把「地质学 / 地球化学」「地球物理学 / 物理学（地球物理方向）」
  印在同一章、目录给同一个页码。取「下一页」时要找页码**严格更大**的条目，否则会算出 `start>end`
  的空区间把整章丢掉；两份方案内容相同，靠 `合章` 字段说明，不假装它们不同。
- 模块归类按页内纵向顺序推进：表归到它上面最近的模块标题；**跨页续表沿用上一页的模块**——
  模块状态（当前模块 / 是否在替代表里）必须跨页保留，按页重置会把课程全丢进「课程」。
- 学分结构是**两列**排版，一行里会出现两个模块（`2．专业必修课程：51 学分  2-2 专业核心课：10 学分`），
  必须整行 `finditer`，行首 `match` 会漏掉 `2-2`。
- 同一件事各院系写法不一：`授予学位类型` / `授予学位名称` / 「达到学位要求者授予法学学士学位」；
  `毕业总学分：131 学分` / 「须修满 133 学分方能毕业」。主表达式 + 兜底表达式；**原文没写就留空**
  （例：法学专业原文「授予学位类型：」后面就是空的，库里也空着，不补）。
- 有个坑：每一节都有一句全校统一的套话「符合学士学位授予条件的，授予学士学位。」，
  兜底取学位时必须先把这句删掉，否则每个专业都会被抽成「学士学位」。
- 辅修卷的表更麻烦：**表头行用 `''` 占位、数据行用 `None` 占位**，只有把两者都丢掉，表头和数据行
  才落到同一个列序上；否则课程名会取到学分那一列。行比表头短时按「实践总学时 / 选课学期」补位。
- 还有个坑：辅助层正文里写「主修修过同名课，须从选修里挑别的替代」，**不能拿「替代」两个字当
  替代表开关**，否则紧随其后的必修表会被整张搬进 `替代课程`（信科的双专业就这么丢过必修表）。
  只有 `说明 / 附：/ 注：/ 可替代课程列表` 开头的行才引出替代表。
- 辅修卷有的模块标题**没有编号**（`专业必修课：31学分`），要单独兜一条规则；兜的时候必须要求
  名字里含「课/组」，否则会把「辅修专业要求的总学分：31学分。」也当成模块标题。
- 还有个坑：**一个位置给一串备选课**。经济学（国家发展方向）专业的「专业基础课」把
  `高等数学（B）（一）/ 数学分析 / 数学分析（I）/ 数学分析 I（实验班）/ 数学分析 1 / 高等数学 A（一）`
  并列，全都标成「专业必修」——直接求和得到「必修 147 学分 > 毕业总学分 124 学分」。
  处理办法：逐模块按培养方案自己写的模块学分（`2-1 专业基础课：18～20 学分`）**等比压缩**，
  并置 `必修_含备选: true`，同时保留 `必修_课程学分和` 原始值。认知卡里会显式提示「并列的课程名是任选其一」。
  全库 49 个章节命中这个坑。**权威数字永远取 `专业必修学分_方案原文`**（照抄培养方案写的
  「2 专业必修课程：N 学分」），课程表算出来的那个只用来做结构比对。
- 还有一类章节（35 个，多为项目/附录/说明，也包括世界史专业、政治学经济学与哲学专业）
  的课程表**没有「课程性质」列**，无法区分必修/选修；指纹按全部课程算并置 `必修_无性质列: true`，
  这类章节只能当画像看，不能当必修清单用。
- **重算指纹不能把共享数据算没了**：`--refingerprint` 是对「已经摘过公共课」的 plans 再跑一遍
  `split_public`，此时「哪门课属于哪个专业」的证据已经不在 plans 里了，必须从上一次的
  `public_courses.json` 继承 `出现于`，否则重算一次 15 门共享课只剩 2 门（实跑踩过，
  `check_split.py` 立刻全线报错）。改完它才真正幂等。
- 能力标签（数学/计算/语言/实践学分）是**词法匹配**，词表要防太宽的词：
  一开始把「信息」放进计算标签，结果信息管理系的「信息计量学」「信息资源管理基础」被算成计算课。
  现在词表在代码里显式列出，每学年人工过一遍。

**关键结论**：课程结构确实能认院系，但**低年级只能认到院系，认不到细分专业**——

## 7. 边界与风险（别把这版当成完备）

1. **医学部、深研院、软微不在本部专业目录里**，需要各自的数据源；基础医学、临床医学
   （以及部分药学方向）因此没有 L1/L2。
2. **文科卷里有 10 个外国语学院语种没有培养方案章节**（印地语、希伯来语、意大利语、梵语巴利语、
   波斯语、缅甸语、菲律宾语、蒙古语、越南语、印度尼西亚语）——目录里有专业记录，正文里没有方案；
   印尼语的章节存在（目录写作「印度尼西亚语」，与章节名「印尼语专业」不同名，靠人工核对才连上）。
   这 10 条就是 §6 里说的「150 条骨架 − 139 条有方案」的差集，**答复时要说明只有骨架**。
3. **一个专业的位置可能印着两个专业**（理科卷 2 组：地质学/地球化学、地球物理学/物理学（地球物理方向）），
   课程表是同一份，卡片带 `合章` 标记，不要当成两条独立的必修结构。
4. **学分是区间**（`43～49`、`2～8`），匹配时按区间处理，不要取中点当事实。
5. **选修课是菜单不是要求**：经济学专业选修课列了 48 门供挑 26 学分。指纹只统计必修；
   选修菜单只能用于「可选什么」，不能用于「必须什么」。
6. **必修课里也可能有备选**（见 §5）。这类专业要读 `必修_含备选`、`必修_课程学分和` 与
   `专业必修学分_方案原文`，认知卡已经带了提示语。
7. **35 个章节的课程表没有「课程性质」列**（多为项目/附录/说明，也有世界史专业、政治学、
   经济学与哲学专业），指纹只能按全部课程算，看 `必修_无性质列` 标记。
8. **同名不同码 / 一码多方向**：`070101` 对应数学与应用数学的三个方向；匹配要用「专业名 + 方向」。
9. **辅修层有两处没结构化**：p5–10 的《辅修/双专业互斥一览表》是双栏排版，`extract_text` 出来的
   次序交错，强行切表只会造出错行，目前只能回原 PDF 查；原文里还有错别字
   （「自然地理与资源环境专辅修」），照抄进库没有清洗。
10. **辅修与主修的课号是同一个体系**，所以「主修修过这门课」要用 `替代课程` 判断，
    不能用课号去重（原文的替代表就是为此存在的）。
11. **年度版本**：主修是 2026 版、辅修是 2025 版。schema 里带 `卷`，专业主键**不要**写年份，
    便于逐年替换；两层的年份差要如实说。
12. **指纹的关键词表是词法匹配**，词表太宽会误判（「信息」会让信息管理系的课被算成计算课），
    所以每张卡都附带命中的课程名原文供人核对，词表每学年过一遍。
13. **留一验证是自洽性验证**：成绩单取自同一份知识库，证明的是「课程结构足以区分院系」，
    不等于真实成绩单一定认得出（真实成绩单还有辅修、双学位、转专业、通识）。真实日志回归要等有用户数据。
